# Outworld dev notes

Privacy gateway in Go that speaks the OpenAI and Anthropic Messages APIs. Public open-source project (Apache-2.0): keep every file free of references to any private environment, machine, host or personal path.

## Layout

- `pkg/entity` entity types, policy actions, `Span`.
- `pkg/detect` detectors: `RegexDetector` (all pattern detectors, `regex.go`), `DateDetector`, `DictionaryDetector` (CSV/JSON, aliases, first/last-name-only, joined handles, optional gender column; `names.go` holds the common-word name-context guard `NameUseOK`), `NERDetector` (HTTP sidecar, code point offsets). `Resolve` picks non-overlapping spans (longest, then priority). `RunAll` runs detectors concurrently for texts of 8 KiB or more and keeps result order; `RegexDetector` does the same per pattern.
- `pkg/detect` ID, bank and secret formats: `RegexDetector` runs `allPatterns` (`regex.go` plus the groups below). A pattern is a regex or a hand-written `scan` func, with an optional cheap substring `gate` that must pass before it runs; `labelSet` finds multi-word labels by a two-byte index instead of a regex alternation. `govid.go`: `national_id` tries anchored national formats at token starts (strong formats need only their checksum or structure, weak ones also need their own cue word on the same or previous line) and `labelled_id_intl` takes the first ID-shaped value within 48 bytes after a multilingual label. `idchecks.go`: the checksum functions, card prefix rules, IBAN lengths, base58check. `finance.go`: cards (sub-span retry at group boundaries, adjacent expiry and CVV), IBAN by country length and mod 97, crypto addresses, labelled BIC, sort code, bank numbers, CVV, expiry. `secrets.go`: vendor token shapes, key=value secrets, auth headers, cookies, CLI credentials, `credential_cue` (password-shaped token near a credential word, scored by `credScore`), the unlabelled password shape (shares the `high_entropy` name), recovery codes, seed phrases, and `highEntropyValid` (rejects lockfile hashes, public keys, base64 of text, identifiers, paths). Every new format needs negative cases in `govid_test.go`, `finance_test.go` or `secrets_test.go`.
- `pkg/detect/address.go` non-US addresses (US forms and `po_box` stay in `regex.go`). Each `addrCores` entry is a regex for the street part only (street word plus house number, either order); everything after it is read by hand in `addrTail`: unit parts (`addrUnits`: `2º B`, `2n 1a`, `Appt 12`, `Top 3`, `bis`), then a postcode and city (`addrPostalCity`: optional country prefix such as `CH-`, multi-word cities through `addrCity`, a trailing country from `addrCountries` in `geo.go`), or for UK cores town words up to a postcode (`addrUKPostTail`) or `, Town, UK` (`addrUKCountryTail`). A core marked `addrTailEURequired` or with a UK tail kind is dropped without its tail; unit parts without a postcode are kept only in the `º`/`ª` form. `addrCity` takes one bare capitalized continuation word only when no further capitalized word follows it or the pair is in `addrTwoWordTowns` (`geo.go`), so it stops before a person's name; more words only after a lead word (`addrCityLeads`), and `am`/`an der`/`aan den` only before a word in `addrRivers`, so the span stops at the city. `address_postal_city` masks a bare postcode and city only next to a cue (`Adresse:`, `c/o` line, PO box line) or a street-shaped line or comma segment (`addrAdjacent`); `address_uk_town` masks town plus a spaced UK postcode with a real area code (`ukPostcodeAreas`). A `c/o Name` part between street and postcode is left to the name detector, so that address comes out as two spans. The stand-in generator must be able to re-detect its own output: when a new tail shape is added, check `TestLocaleAddressSurrogatesSurviveRemasking`. Exact-span cases and negatives live in `address_test.go`; `slugPath` in `regex.go` keeps `high_entropy` off word slugs (lowercase words and digits joined by `-`, `_` or `/`, at least half of the bytes in real words).
- `internal/textutil` `Fold` (lowercase, accents to ASCII); every name-table lookup goes through it.
- `internal/namedata` embedded given-name and surname tables (US government data, Wikidata, per-country lists; keys are folded ASCII; `merge_intl.py` rebuilds them); `pkg/detect/namedetect.go` is the model-free `NameDetector` built on them (full names, lone first names, particles, surname-first, initials, lowercase full names, labels, kinship, chat speakers, profile slugs, with tech-term and common-word guards). `familyfirst.go` adds family-name-first Vietnamese, Chinese and Korean names (the span carries a given-first `Canonical`, so role assignment gives the first token a family surrogate). `handles.go` finds code handles in username positions (TODO parentheses, branch user prefixes, @mentions, home directories, git trailers; source `names:handle`, single-token handles get a `person.joined` surrogate built from the surname surrogate). Sign-offs also cover a line holding only a dash (`--`, `-`, en or em dash) plus a first name or full name (`dashSignRE`; a lone single word must be a given name that is not a common word or state, and after a single `-` not a weak one). A given name with a possessive `'s` right after a comment opener (`//`, `#`, `/*`, `*`) is a lone first name (`commentPossessiveRE`; common words, months, weekdays, states and tech terms excluded). `orgguard.go` drops person spans that match `internal/namedata/companies.txt` or are followed by a corporate word and emits a kept `org` span instead; dictionary entries, honorifics, kinship, sign-offs and strong labels still win. Name-detector context rules (all in `pkg/detect`, each with positive and negative tests in `gaps3_test.go`):
  - `names.go` `personVerbAfter` / `personDirectedBefore` are the shared sentence-context checks (strict single-space adjacency via `wordsAfter` / `wordsBefore`).
  - Technology homonyms (`greeting.go`; tech terms that are given names or surnames, plus `nameLikeTech`, the planet names): `TechContext` is true only on strong evidence right next to the name (code span or identifier, version, a `techCompoundNouns` word right after, a `techVerbsBefore` verb right before, `on rails`, `<style> case`), and `PersonShape` (possessive, honorific, relation word, object verb, auxiliary question, person verb after, hyphenated name part) always beats it. In `pkg/outworld/session.go`, `homonymPersonUse` masks every prose use of a vault-known or same-request homonym. A Capitalized or all-caps name keeps only inside an inline code span or a closed fenced block (`VaultNameKeep`), and only when that region holds no other vault-held name and no other title-case name-table word within `contextWindow` bytes, and the span is not a bare name followed by `'s`. Lowercase forms keep by token shape (`strictIdentifier`): joined by `-` or `_`, or dotted with three or more segments or a `fileExtensions` extension right after the name, and never when another part of the token is a vault-held name. Outside fences, any keep is voided when the same paragraph (text between blank lines) also holds a vault name of the other kind, raw or already masked (`pairInParagraph`), and a token that overlaps an earlier person replacement never keeps (`personInsertionInToken`). Code regions (`coderegions.go`) are computed once per text in one linear pass and cached: a fence opens at a line start (up to 3 spaces, no tab) with three or more backticks or tildes and closes with the same character at least as long; an unclosed fence is not code, indented blocks are not code. Inline spans pair backtick runs of equal length within a paragraph; a run cannot open after a letter or digit, after an odd number of backslashes, when it is a line-leading run of three or more, or when 1 or 2 ticks are followed by a word and an apostrophe (TeX and British quotes); a single tick between two letters is an apostrophe; a lone or unmatched tick is never a span. Paired paragraphs (`paraNamesFor`, `pairedVaultWords`): when a paragraph holds both a vault given name and a vault surname (any case, raw, masked, or inside a glued token), every occurrence of a vault name in it masks with the vault's own record, whatever the case, joiner or distance, with adjacent digits and one trailing `s` folded into a `person.joined` record so the stand-in restores as a whole word. Only lowercase, digit-affixed or trailing-`s` forms go this way (capitalized words keep the `realHit` guards), and function words that are also names (`will`, `may`, `detect.StopWord`) never do. Outside such a paragraph a lone lowercase common-word name (`ruby`) follows the vault's capitalized-only rule and stays as written. Glued forms (`gluedVaultNames`) split each letter run of 6 to 40 runes, folded, into given plus surname or surname plus given (one trailing `s`, adjacent digits); a token with an inner capital (`RubyKelly`, `rubyKelly`), or with an affix, gets per-part casing (`FenellaDalrymple`), and `spellingForm` keeps that per-part shape when it records a form, so it restores byte for byte. Three glued names, two given names, and initials (`ruby k.`) are not matched; two vault surnames that form one hyphenated surname are (`smithjones`), as is a surname with a dropped o or d particle (`obrien`). A function-word given name (`will`, `may`) masks only when one joiner run or a glue joins it to a vault name of the other kind; in surname-first order it needs a comma (`Smith, Will`), Title case on both words (`Smith Will`) or a joiner without whitespace (`smith.will`, `smithwill`), so `Smith will call` keeps the verb (the learned dictionary's spaced surname-first form of such a name also needs both words capitalized). Within one text, once any occurrence of a vault name masks, every keep of that word in the same text is void (`maskedInText`). Exact restore for every spelling: when an occurrence's stand-in would not rehydrate to the request's own bytes (accents added or removed, `ß`/`ss`, `ø`, combining marks, fullwidth, irregular case, a dropped particle or hyphen), `spellingForm` derives a variant from the base record's surrogate (the input's case and width pattern applied to it, a doubled vowel when that collides with a plain form of the base) and records a `name.form` (exact real bytes to exact emitted bytes) that `FindForms` restores before any surrogate match. Forms are queued per request and written in one durable update at the end of `Mask` (`commitForms`); at most `vault.MaxNameForms` (16) per base name and `MaxNewFormsPerRequest` (64) per request. Beyond the bounds the occurrence still masks with the base stand-in and restores to the vault spelling. Combining marks are part of name tokens and spans and are stripped from stand-ins. A tech-homonym given name followed by lowercase particles and a capitalized surname (`Ruby van der Berg`) is a full name with person evidence. `techPersonUse` masks a vault-known assistant name only with a person shape, and every bare use when the request names the person in full (`techNameAnchored`). Tests: `pkg/outworld/vault_homonym_evidence_test.go` (table tests in all four vault modes), `tech_given_cross_test.go`, `pkg/detect/vaultkeep_test.go`.
  - `familyfirst.go` `familyContext` accepts an ambiguous family-first pair (`Sun Yang`) as subject of a person verb, object of a person-directed verb, after `with/from/cc/by/to` plus a comma or person verb, or as a possessive; `familyListed` accepts one next to a multi-word person in a comma or `and` list. `englishSyllablePairs` (English words that parse as two name syllables, such as `Range`, `Dance`) never count; `englishSyllables` (`Long`, `Moon`) only count with a verb.
  - `orgguard.go` `companyPeople`: a listed company is emitted as a person (`names:company-person`) only when it is person-shaped, has person evidence, and no occurrence of that name in the same text has company evidence (`companyEvidence`: company verb, `at/of/for` before it, `from` before it when a capitalized name or a person verb such as `called`/`hired` precedes `from` (`Kevin from Morgan Stanley`), possessive, `said it`, or a corporate noun in the sentence). Mixed or absent evidence stays org.
  - `handles.go`: an @mention is taken as a whole token or not at all (`@jsmithLane` is left alone). `proseHandleSpans`: a lowercase handle in prose needs a cue word right before it and a handle shape from the name tables; `per/from/by/with` need the strong shape. `gitHandleRE` covers `git push|pull|fetch <remote>`, `git branch|switch|rebase|checkout`, `gh pr checkout` and prose cues (`PR from`, also with a number between such as `PR #412 from` or `MR !17 from`, `rebased onto`, `based on`, `off of`); `git log|diff` and `user:branch` fork refs need `personalHandle` (an initial-plus-surname or first-last shape, never a lone dictionary name, because those positions also hold paths and `key:value` text). `todoName` lets a known first name through inside TODO-style parentheses even when it is a stop word (`will`, `may`, `bill`, `april`, `june`); `todoTopics`, tech terms and service accounts stay. New English false positives go into `internal/namedata/handlewords.txt` (kept in byte order).
  - `namethings.go` `thingAt` / `NamedThingUse`: a name token is a named thing, not a person, when it sits in a phrase from `internal/namedata/phrases.txt` (multi-word places and terms such as `monte carlo`, `turing test`; folded, byte order), after a place lead (`San`, `Saint`, `St.`, `Mount`, `Lake`) or thing lead (`Room`, `Hotel`, `Hurricane`), before a capitalized `thingNouns` word (`The Amber Room`, `Darwin Awards`), before a lowercase eponym noun (`Turing test`), before a region code (`Regina SK`) or an appositive (`Darwin the macOS kernel`). A phrase line ending in ` *` is also shaped like a personal name (`tom collins`, `glen allen`): `phrasePerson` reads it as a person again on person evidence (`strictPersonEvidence`: person verb after, person-directed verb before except `visit/saw`, greeting, role, honorific or people label before, or a further name word next to it), never after a determiner or `at`. The region-code rule (`regionShapeAfter`) needs the code right after the name (`City XX` or `City, XX`) followed by punctuation, a line end or a digit, or a place preposition before the name; a greeting before the name turns it off, so `Maria, PE class is cancelled.` stays a person. A thing noun that is also a surname (`Hall`, `Park`, `House`) is a person only with `pairPersonEvidence` (person verb, directed verb, `with`, role or label before; never after `the` or `at`) or after a strong first name. The same check runs for lone dictionary and learned name tokens (`dictionary.go`) and for the leak check's known-real scan through `NameUseOK`, which also asks for person evidence before a lone tech-term name (`Ada`, `Julia`) counts. A full name before a capitalized `commemorativeNouns` word (`Grace Hopper Award`, `John Smith Memorial Fund`) is handled by `trailingThing`: skipped when an article stands before it or there is no person evidence before the name; with evidence the name is masked, and when the trailing noun is also a surname (`Hall`, `Park`, `House`) and nothing capitalized follows, the noun joins the name (`We met Mary Smith-Jones Hall`). Tests: `names2_test.go` in `pkg/detect` and `pkg/outworld`.
  - `namelists.go`: `nameLists` reads comma or semicolon lists after a people label (`Present:`, `Attendees:`, `Cc:`, `Participants:`, `Team:`, `Invited:`, `Apologies:`); when the list has a clearly named person, capitalized pairs with a common-word first name and (for attendee-style labels) lone unknown tokens are people too (`names:list`), and the comma surname-first rule is off inside it. `surnameLed` also refuses `B, C` when a name word stands right before `B`. `capsSurnameFirst` takes an all-caps run of surname-table hits and particles before a comma plus up to three given names (`names:surname-first`, given-first `Canonical`); leading caps words that are not surnames or are label words (`PATIENT`, `INVOICE TO`, a postcode) are left out of the span, and after a common leading word a single weak surname is not enough (`PLEASE READ, Daniel`). `honorificNames` covers lowercase and non-English honorifics with up to four name tokens plus particles (`names:honorific`; `don`/`doña` give `names:don`, a given name); after a lowercase honorific a lowercase token counts only when it is a strong name-table hit (one surname, or a given name plus a surname), never after an article and never a listed verb form (`frau schmidt rief an` gives `schmidt`). `initialismSpans` masks an all-caps token of 2 to 3 letters that equals the initials of a multi-word person found in the same text (name detector spans, or dictionary and learned entries matched in full), only in a person position; tokens in `CommonInitialism` (abbreviations, state, province and country codes, short words) need a speaker label or a list slot. The surrogate is stored as `person.joined`, built from the initials of the name surrogates already in the vault, and is never a `CommonInitialism`.
  - Scale: every line, sentence and context lookup in the name and dictionary detectors is limited to `contextWindow` bytes around the token (`lineBounds`, `sentenceBounds`, `NamedThingUse`), list elements and company matches are found by binary search or an offset index, and `TestNameDetectorsScaleLinearly` (`names4_test.go`) times 256 KiB single-line inputs. Any new per-token helper must not scan to a line or text boundary.
  - `dictionary.go`: derived joined handles (`jsmith`, `johnsmith`) do not match CamelCase text. The initial forms (`JSmith`) are skipped everywhere, full joins (`JohnSmith`) only in code positions; a form listed in the dictionary always matches. The leak check's known-real scan skips CamelCase hits on `person.joined` records for the same reason.
- `pkg/vault` `Vault` (in-memory index, real/surrogate matchers) over a `Backend`. `FileBackend` = magic header + length-prefixed AES-256-GCM frames, frame index in AAD, frame 0 holds the vault secret, `flock` on `<path>.lock` for multi-process writers on Linux, macOS and the BSDs; elsewhere single process only, with an exclusive `<path>.lock` (created with `O_EXCL`) held from `Load` until `Close`, and a second open fails naming that file. Truncated tail frames, and a tail that is all zeros or all zero-body frames to EOF (torn extend), are dropped on next write.
- `pkg/surrogate` HMAC-seeded generators and bundled name lists.
- `pkg/dateshift` date finding (English plus es, de, fr, pt, it, nl month names, compact and spoken forms; dotted dates read day-month), format-preserving shift; `FindLoose`/`ShiftLoose` are the lenient variants used for rehydration; yearless dates shift cyclically within a 365-day year so they round-trip.
- `pkg/outworld` `Engine` + `Session` (mask, leak check, rehydrate, `StreamRehydrator`, unknown-name flags).
- `internal/config` YAML schema (strict, unknown keys rejected). The eval harness writes configs against these keys; do not rename them.
- `pkg/outworld/memo.go` transcript memo (real text to the exact masked bytes already sent, per scope, LRU by bytes); `learn.go` builds a per-session dictionary from person spans found anywhere in the request, including names inside `first.last@` email addresses.
- `internal/gateway` HTTP server, routing, request masking, response and SSE rehydration. `anthropic.go` and `anthropic_stream.go` are the Anthropic Messages path.
- `internal/app` builds an engine from config. `cmd/outworld` CLI.
- `detectors/gliner` and `detectors/privacy-filter` optional Python NER sidecars with the same `/detect` contract.
- `eval/` is a separate Go module owned by the eval harness. `corpus.json` is the tuned corpus, `holdout.json` is a development set (detectors were tuned on its misses), `holdout2.json` was blind until its per-type totals steered the secrets and ID work; `holdout3.json` is the blind one now: never read its leaks or its `cmd/genholdout3` item files to tune detectors, or its number stops meaning anything.

## Invariants

- Vault key required; no plaintext fallback.
- `Vault.Assign` runs the generator while holding the vault lock: generator callbacks must not call back into the vault (pre-compute lookups first).
- Leak check runs on every transformed string (detector re-scan + known-real scan, skipping inserted surrogate ranges) and on untransformed fields like message `name` and JSON object keys. In `Session.Mask`, findings that do not overlap an inserted range are masked in place and the text is re-scanned (up to 4 rounds); real text equal to a person surrogate is re-masked so rehydration stays correct (this overrides a kept org span), including a typed CamelCase or glued form of a `person.joined` stand-in (`collisions`). A known-real name next to its own surrogate is not a violation when the only uncovered words are single letters or name particles. A person or strip-type finding that partly overlaps a replacement has only its uncovered words masked (vault kind `person.residue`, or a `[redacted ...]` placeholder). After the rounds settle, the uncovered remainder of any first-pass span that lost an overlap in `Resolve` is masked as its own type when it holds two letters or four digits. One real word has one surrogate: a name record adopts an existing residue surrogate, and the known-real scan skips a residue hit only when no family, given or nick record exists for that word. Only residual findings (and any finding from `Check`) become violations: 422 with `findings` whose previews always show `[***]`, never any character of a value. `X-Outworld-Dry-Run: 1` and `outworld dry-run` run the same path and stop before the upstream call (they do write the vault and memo).
- The gateway masks each request twice: a priming pass (`Session.SetPriming(true)`) detects every text, caches spans and assigns surrogates without changing anything, then the real pass masks with the vault already knowing every name in the request.
- Person surrogates: role (given/family/nickname) comes from the dictionary canonical name, else position. Nicknames get their own vault kind `person.nick`, derived from the first-name surrogate. Reals are stored in canonical casing. Given-name surrogates follow `surrogate.GenderOf` or the dictionary `gender` column. Family-first spans (`names:family-first`, and learned repeats tagged `learned:family-first`) draw from the per-origin pools in `pkg/surrogate/eastnames.go` (Vietnamese, Chinese, Korean; `EastOrigin` picks by family name, middle marker and hyphen): the first token gets a family name from the pool, every other token a given name or syllable with the same hyphenation and casing, and a middle marker (`Van`, `Thi`) stays in place unmasked. Pool entries are at least four letters (shorter lowercase surrogates would not restore), are not English words, and do not overlap each other or the general lists; when a pool is used up or blocked by real names the general lists take over. A lone hyphenated given name (`Min-jun`) reuses the given records. Other shapes keep the older position rule (`Mary Smith-Jones`, and a hyphen part with no given record, are family) so existing vault records do not move.
- A name particle (`van`, `der`, `de la`, `y`, ...) inside a person span that is not its last word and has no person record in the vault is kept as written (lowercase anywhere, capitalized after the first word), and only the name words get stand-ins (`detect.IsNameParticle`); particles never become vault records, also not through joined handles (`joinedSurrogate` keeps them literal). A particle that a legacy record holds (released vaults, `Vault.Legacy`) keeps producing its recorded stand-in; a record written by this version (`Ruby Van called`) does not turn a later mid-name particle into a stand-in, and family-first middle markers (`Van`, `Thi`) are unchanged. A person span followed by a particle run and a capitalized surname-like word extends over them (`particleTails`: `García de la Fuente`, `Ortega y Gasset`), a dangling particle does not hide the given name's person evidence (`PersonActionAfter`), glued handles join the first pass with their records so they own the whole letter run, and a person replacement that covers only part of a letter run masks the rest when it is a vault name (`runRemainders`), also when particles sit between them, glued or behind `.`, `_` or `-` (`RubySt.John`, `RubyDe.La_Cruz`): the particles are trimmed for the lookup and kept literal inside a `person.joined` record for the whole run (`particleTrimmed`, `affixedJoined`). A particle that ends the name (`Ruby Van called`, `Ruby van called`) is the surname: masked and recorded; such short records match only capitalized forms, and a lowercase particle word never counts as a vault name in the lowercase rules, so `a van arrived` and `de la rue` stay. `St.` and `Ste.` (with or without the period) are particles; a vault surname right after `St.` is a person although `St.` is a place lead. Glued detection joins runs across apostrophes (`'`, U+2019, U+02BC), and across `.`, `_` or `-` only at a particle joint (`particleJoint`: `rubyst.john`, `ruby.stjohn`, `rubyo-brien`) or when the whole token holds a particle segment or a particle-affixed vault name and splits into a vault given name and surname (`particleToken`: `ruby.johnst`, `john.struby`, `brien.oruby`), in either order and with the particles before, after or between the parts (`nameRealLoose` also strips trailing particles from a surname part); it accepts a nickname as the given part. A concatenation of particles (`DeLa`, `VanDer`, also hyphenated `De-La`, which the detector accepts between a given name and a surname) counts as a particle everywhere a particle is kept literal. Particle-literal rule in `personSurrogate` (`particleLiteral`): a particle with no legacy record is kept as written when a non-particle word follows it later in the span (at the start of the span only when it is lowercase, inner in the canonical name, followed by a joiner and a capital, or followed by another particle); a trailing run of particles is kept only when it is attached by a joiner without whitespace and an earlier word of the span was a vault surname before this span was masked (`Ruby-John-St` after `Ruby St. John`); otherwise the trailing particle is the surname and masks (`Ruby John Van called`, `Maria Luisa De`). A particle word that the vault holds as someone's given, family or nick real is never kept literal at either edge of a person span (`van Ruby`, `De-Kelly`), and next to a person replacement it masks with that record (`heldParticleNeighbors`); between two name words it stays a particle (`Vincent van Gogh`), and a lone lowercase particle in prose is still never a vault name (`a van arrived`). A span made only of particles (`De La` after an honorific) stays as typed. The street-abbreviation exception below yields to a held real too. The exception is `St` and `Ste` (with or without a period) at the end of a name span: they are read as a street abbreviation (`John St`), never as the surname, and stay as typed (`Ruby John St`, `Maria Luisa St`, `Ruby St called`, while `Ruby St. John` masks); the detector's `particleEndRE` does not extend a span over them, `particleLiteral` keeps them through `detect.StreetAbbrev`, and `PersonActionAfter` looks past them, period included, for the given name's person evidence. Glued letter runs also split after stripping up to 8 letters of particles from the start and from the end (`johnrubyst`, `vanderrubyberg`), but only into exactly two vault names. A lowercase run that is a vault given name syllable plus another vault name part (`dabit`, `da-bit` after `Da-bit Lee`, `syllableGiven`, first part a one-syllable East Asian given name) counts as that given name. A rejected `person.joined` hit is rescanned for the vault names inside it (`innerReals`), so a stored handle never hides its parts. A lowercase vault name joined to a single initial (`f.lefevre`, `francois.l`) masks without a cue word, and a vault name glued to one initial letter (`rubyk`, `kruby`) masks with the initial kept when the vault holds that handle as a joined record or another part of the same token is a vault name (`initialRuns`). A joined record also matches with leading or trailing digits (`ruby_k99`, `digitAffixedJoined`), and digit-only leftovers of a person span are never masked as a residue name. New given and family stand-ins never contain the real or, for 5 or more letters, any root of it after stripping particles (one-letter o, d and l included) or splitting hyphenated parts (`notContaining`; `TestStandInsNeverContainTheRealRootUnderAnySecret` walks the generator over many secrets). Cost: every vault-name lookup on letter runs goes through a name-key index built with the fold index (`nameKeys` in `foldindex.go`: folded, letters-only keys of given, surname and nick reals, their lengths and two-letter prefix and suffix filters). `nameReal` rejects a word whose key is not in it, `runName` and the glued split skip runs with no key near both ends (`nameRunPossible`), the glued split tests only cuts with a key ending near the cut and one starting after it (`nameSpan`), and `scan` skips the vault-name passes when the vault holds no names. `TestNameMatchingCostOnLongLetterRuns` bounds long-letter-run structured text against English of the same size and a 50-person vault against an empty one (1.3x). `runRemainders` walks over particle segments on both sides of a person replacement (`forwardParticleRun`). In the quoted-nickname shape (`Robert "Bobby" Kelly`, also single quotes and parentheses) the word after the nickname is a surname (`names:nick-surname`, family role); vaults seeded earlier hold that word as a given name, so the glued split still accepts a given record whose word is a table surname on the surname side. After a one-letter o, d or l particle any single non-letter, non-digit, non-space rune (or a modifier letter) joins a glued run (`rubyo`brien`), while a possessive `'s` never does. A vault surname whose word is a particle (`Van`, `De`) counts only with person evidence (`particleSurnameEvidence`: an honorific or vault given name right before it, a vault given name in the paragraph, or `detect.PersonEvidence`), also for learned spans. When a person replacement sits next to another vault name of any kind (one joiner run, not a function word), that name masks too (`adjacentVaultNames`).
- Handles never carry the real initial: `handleSurrogate` and the handle branch of `personSurrogate` take the initial from the given-name surrogate when the person is known in the request (dictionary or learned full name), else a keyed letter from `Generator.Initial` that differs from the real one. Dotted and underscored handles with an initial (`k.chen`) are stored whole as `person.joined`. Records written before this keep their stored surrogate. Prose initials (`J. Smith`) are unchanged.
- Vault compatibility: the first write by this version adds a hidden `vault.format` record; records before it are legacy and keep producing the bytes the earlier release produced (`pkg/outworld/testdata/head-vault.*` pins this). Initialism surrogates (`JRA`) are stored as `person.joined`, avoid every all-caps token in the request, and restore only on an exact-case whole-word match.
- `name.form` records map one exact emitted stand-in to one exact real spelling (at most 16 per base name, fold key); they are indexed with the phone forms and never added to the real matcher, and vaults without them open unchanged. A form only matches between non-word runes (no letter, digit or combining mark on either side, `nameFormBounded`), the stream holds a complete form at the buffer end until the next rune arrives, and a form's stand-in may share a normalized key only with records of the same base name, never another person's.
- `Engine.DateOffset` is never a multiple of 365 days, because yearless dates shift within a 365-day cycle and would otherwise go out unchanged.
- Detector scans are bounded: every line or context lookup in `pkg/detect` reads a fixed window (256 to 512 bytes) around the candidate, never the whole line. `scale_test.go`, `TestNameDetectorsScaleLinearly`, `TestUnbrokenWordsScaleLinearly` and `TestAddressScansStayLinearOnOneLongLine` time long single-line inputs; new rules need a case there. Word walks (`wordBefore`, `wordAfter`, `wordsBefore`, `wordsAfter` and the like in `names.go`) stop after `wordScanLimit` (64) bytes. `internal/scaletest` measures process CPU time (wall clock where the platform has none), runs one measurement at a time, and under the race detector shrinks inputs by 16 and only logs. Generated matrices in `pkg/outworld` tests seed once and give every row its own clone of the seed-only vault (`modeRunner`: an in-memory clone for same and new, a copy of the seeded file plus a real reopen for reopen, a fresh vault for anchored, and the first row of each mode file-backed); test file vaults use a fixed secret (`vault.NewFileBackendWithSecret`) so stand-ins are the same on every run; stream restore is checked on every row, and under the race detector rows are sampled with a seed printed in the log (`OUTWORLD_RACE_SAMPLE` repeats it). `scaletest` stops early only after three runs with two consecutive growth ratios under 12x. A panic inside a pattern is recovered and returned as a detector error, so the request fails closed.
- Rehydration restores dates via the session's exact shifted-string map first (style-ambiguous forms like `May`), and phones by digits (`Vault.ReversePhone`) in any formatting.
- Byte stability: anything already sent upstream must be re-sent byte-identical (prompt caches and Claude's preserved-thinking prefix check depend on it). `Session.Mask` consults the memo first; the gateway calls `Session.Remember(rehydrated, upstream)` for every model string it translates back. Never rehydrate or re-mask `thinking` blocks. JSON is re-encoded with sorted keys, which is stable across requests.
- Anthropic path forwards `anthropic-*` headers, query string, unknown fields and upstream error bodies unchanged.
- Logs carry counts and routes only.
- Streaming: `StreamRehydrator.safeCut` holds back any tail that could be the start of a surrogate or a date, and `avoidStraddle` never cuts inside a complete match. `Push` also holds back a trailing incomplete UTF-8 sequence, so chunks may split inside a character.
- Address surrogates: `surrogate.addrLocaleOf` reads the country from the real address (`address_locale.go`); a recognized locale gets street words, a town and a fitting postal code from that locale's lists, and multi-word street and town names keep their word count and connectives. Number-first ES/PT/IT/DE/NL forms need a European postcode; a UK address without a postcode is only recognized with a trailing UK country word. A US ZIP ending, a US state code or spelled-out state name, or `USA` always sends the address down the older path. Anything it does not recognize, including every US-style address, takes the older path, whose output is pinned by `TestUSAddressesAreByteStable`: never change those bytes.

## Commands

```bash
go build ./... && go vet ./... && go test -timeout 45m ./...
go test -race -timeout 30m ./...
```

Under the race detector `pkg/outworld` and `internal/gateway` can each take several minutes, so the race run sets `-timeout 30m`.
