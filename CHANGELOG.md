## [0.3.0] - 2026-11-26

This release also covers the commit made after the 0.2.0 tag on 2026-11-22 (code handles, person-named companies, family-name-first names, localized addresses).

### Added

- Blocked requests explain themselves. A 422 now carries `findings` (type, detector, field, position, a fully redacted preview and a one-line hint) and a `help` line; previews never show any character of a flagged value. See [docs/blocked-requests.md](docs/blocked-requests.md).
- Dry runs. Add `X-Outworld-Dry-Run: 1` to any request, or run `outworld dry-run [--api openai|anthropic] [file]`, to get the masked request, every replacement, every finding and the route without calling the upstream. The CLI exits with code 3 when the request would be blocked. A dry run still writes new stand-ins to the vault and the memo.
- National ID numbers checked by checksum or structure, and ID values after a label in several languages. Cards, IBANs (length and mod 97 per country), labelled bank numbers, sort codes and crypto addresses. Vendor API key shapes, `key=value` secrets, auth headers, cookies, CLI credentials, recovery codes, seed phrases and password-shaped tokens next to a credential word. Credentials in URL query strings, and percent-encoded email addresses.
- Non-US street addresses: street-first and number-first forms, postcodes with a country prefix (`CH-8001`), floor and unit parts (`2º B`, `Appt 12`), multi-line blocks and a trailing country line.
- Cued phone numbers and IDs:
  - plural, camelCase, slash-joined and abbreviated labels (`phones:`, `mobileNumber`, `tel/fax`, `ph`);
  - labels glued to the value (`TEL090-1234-5678`, `Tel.090-...`, `SSN_536-22-8471`), while longer words that merely end in a label (`HOSTEL090-...`) are left alone;
  - several cued numbers on one line;
  - continuation labels after a cued phone: in `phone 804-555-1234, work 703-555-2468` the second number is masked too. `work`, `home`, `office`, `direct`, `main` and `desk` count only in that position, after `and`, `,`, `;`, `/`, `or` or `&`.
- Cards after key punctuation: `card=4111...`, `card#4111...`, `pan_4111...` mask when a card word is in the key or earlier on the line. Strict grouped forms (`4111 1111 1111 1111`) mask without a cue. An expiry such as `exp 12/27` is stripped next to a card, and is not treated as a card on its own.
- SSNs: separated forms (spaces, dots, Unicode dashes) are decided the same way as the dashed form.
- Text written with full-width digits, Unicode dashes, no-break spaces, soft hyphens or zero-width characters is detected as if it were plain, and the original bytes are masked.
- Names:
  - Greetings: the target of `Hi`, `Dear`, `Thanks` and similar is masked by default, and kept only on positive evidence that it is not a person: an assistant name (`Hi Claude`, `Hi Siri`), a generic target (`Hi all`, `Dear Team`, `Hello World`), a role pair (`Dear Hiring Manager`), or a product name (`Hi Claude Code`, `Hi GitHub Copilot`).
  - Korean given names such as `Min-jun` and `Seo-yeon`, with gates so that food, place and culture words after a family name are not read as given names.
  - Hyphenated given names (`Jean-Luc`, `Lily-Rose`) are one name, and any Unicode hyphen or an en dash inside a name behaves like `-`. Dash-joined prose pairs (`the Dunning–Kruger effect`, `London–Paris route`) are left alone.
  - Attendee and `Cc:` lists, initialisms of people named in the same text (`LP` after `Liam Parker`), all-caps surname-first names with particles, and Spanish, French, German, Italian and Portuguese honorifics.
  - Named things are not people: multi-word places and terms (`Monte Carlo`, `Turing test`), venues (`The Amber Room`) and `City XX` forms.
  - Code handles count as people in username positions: `TODO(kchen)`, branch user prefixes, `@mentions`, home directories and git trailers. Handle stand-ins never keep the real initial.
  - Well-known organizations that look like a person (`Morgan Stanley`) are kept as `org` unless the text treats the name as a person and nowhere as a company.
  - Family-name-first Vietnamese, Chinese and Korean names, with stand-ins of the same origin and shape (`Nguyen Van An` becomes something like `Kieu Van Phuc`).
- Locale-aware address stand-ins for French, Spanish, Portuguese, Italian, German, Dutch and UK addresses. US-style addresses are generated byte for byte as before.
- Phones restore exactly in almost every case. The vault stores each exact phone stand-in it sends next to the exact original bytes (`phone.form` records), so the answer gets back the original spelling. Before a phone stand-in is sent, the real restore is run on it with up to 16 bytes of its actual neighbours on each side, as they will be sent; when it would not restore, other forms are tried and stored for that context. Two phone numbers right next to each other are both masked and both restore. Superscript and subscript digits right after a number (`804-555-1234²`) restore exactly.
  - A detected phone number is never sent as it is. When no stand-in can be shown to restore in its place, the number is replaced by `[redacted phone]`, which is not restored.
  - One case does not restore byte for byte: a number written in styled digits (mathematical bold, full-width) comes back in plain ASCII digits.
  - Up to 32 forms per number are stored, and up to 256 per number in all for forms that only restore in their context. Phone form records the vault cannot use when it loads are counted, and `outworld serve` logs the count once at startup.
- Gateway setting `max_opaque_bytes` (default 786432, that is 768 KiB). An opaque value (thinking `signature`, `redacted_thinking.data`, `encrypted_content`, `encrypted_index`) whose base64 text is longer than this is refused with 422 without being scanned; the finding has type `oversize` and source `gateway:opaque_too_large`. See [docs/blocked-requests.md](docs/blocked-requests.md).
- Scale tests (`internal/scaletest`) for detectors, masking and the stream rehydrator. They run each workload on an input and on one 8 times larger, take the minimum time of each over five interleaved runs, repeat that up to six times while the check fails, and fail when the larger run still takes more than 16 times as long. A cost of the form a·n + b·n² is therefore flagged only when the quadratic part is at least about 1.3 times the linear part at the larger input. Time is the process CPU time (user plus system) where the platform provides it, and wall-clock time elsewhere, so load from other programs on the host does not fail the tests; measurements run one at a time. Under the race detector the inputs shrink by 16, each size runs once, and the check only logs.
- A third blind evaluation corpus (`eval/corpus/holdout3.json`, `holdout3-people.csv`) and its deterministic generator `eval/cmd/genholdout3`, with checksum-valid invented identifiers and a lint. First scores (README, "How well it works"): 16.2% leak with a dictionary, 20.1% without, 99.3% restore. See [eval/README.md](eval/README.md).
- On Windows and other platforms without `flock`, the vault is single-process: an exclusive `<vault>.lock` file is held while the vault is open, and a second process fails with an error that names that file.
- `outworld serve` shuts down cleanly on SIGINT and SIGTERM.

### Changed

- Route header (security). With `policy.allow_route_header` unset, `X-Outworld-Route` may now only make routing stricter (`block`, then `local`, then `masked`, then `passthrough`); a header that asks for a looser route is refused with 403. Set `allow_route_header: true` to restore the old behaviour where any client could pick any route, including `passthrough`.
- Every field of a request is now checked. Fields the gateway does not know, and protocol fields with an unexpected value, used to go upstream unchecked; they now get the full leak check, and a finding there blocks the request with 422 and names the field. Tool schemas, `metadata`, `prediction`, `stop`, `stop_sequences` and `response_format` schemas are masked. The README section "What is masked" lists every field.
- Technology names that are also given names or surnames follow the ordinary person rules: 46 in all, 23 given names (`Ruby`, `Adam`, `Jasmine`, `Julia`), 18 surnames (`Swift`, `Rust`, `Docker`, `Jenkins`) and the planet names `Mercury`, `Jupiter`, `Saturn`, `Neptune` and `Pluto`. `Hi Ruby,`, `Dear Adam,` and `Hi Mercury,` mask. On a fresh vault a lone use with no person shape, such as `Adam wants a refund.`, keeps.
  - Once the vault knows a person with that name, a later lone use masks by default (`Forward this to Ruby.`, `Ask Ruby about the server config.`). It keeps only on strong evidence right next to the name: a technical noun right after it as a compound (`Kafka topic lag is high.`, `Hugo site build failed.`), a dotted or `v`-prefixed version (`Ruby 3.3 is installed.`), an infrastructure verb right before it (`Restart Jenkins after the deploy.`), a code span or identifier (`` `Ruby --version` ``, `ruby-lang`), or a fixed compound (`Ruby on Rails`, `Pascal case naming`).
  - A person shape always wins over that evidence: a possessive (`Ruby's build is broken.`), an honorific (`Dr. Ruby restarted the server.`), a relation word before (`My daughter Ruby`), the object of a person verb (`Ask Ruby about it.`), a question with an auxiliary (`Did Ruby see the error?`), or a person verb after (`Ruby said the deploy failed.`).
  - When a request names the person in full (`Ruby Smith`, `Claude Shannon`), every other bare use of that name in the same request masks, even next to technical words (`Ruby Smith maintains our Ruby 3.3 services.` masks both), except in a code span or identifier.
  - Assistant names (`Claude`, `ChatGPT`, `Gemini`, `Copilot`, `Siri`, `Alexa` and a few more) keep when used alone on a fresh vault (`Hi Claude,`, `Claude said the API is down`). Once the vault knows a person with that name, a later lone use masks when the sentence has a person shape (`Claude wrote most of this module.`).
- `outworld mask` runs the same two passes as the gateway, so every name in the input is known before anything is replaced.
- Streaming rehydration gives the same result as restoring the whole answer at once, including stand-ins split across chunks. The holdback is bounded, and a long unbroken run (for example base64) is cut mid-word, so it streams in linear time instead of being held to the end. Long runs of digits, or of letters and digits, now stream at about the cost of plain text: a test holds each within 1.5 times the time of plain text, also with a 200-byte stand-in in the vault.
- Vault writes are durable: a new vault file is written through a synced temporary file and directory, and a tail of zero bytes left by a crash while the file was being extended is dropped on the next write, like a truncated frame.
- Dates in `version:` and `api-version=` style labels are no longer shifted. Dates in URL paths are still shifted.

### Fixed

- Yearless dates could go out unshifted when a scope's date offset was a multiple of 365 days. The offset now never is.
- A split UTF-8 sequence at a stream chunk boundary is held back instead of being sent broken.
- Long unbroken words (a base64 blob with no spaces, or capitalized names glued together) no longer take quadratic time in the name detector: every walk back or forward over a word stops after 64 bytes.

### Security

- Opaque gateway fields (`signature`, `redacted_thinking.data`, `encrypted_content`, `encrypted_index` and similar base64 values in assistant turns) are no longer forwarded unread:
  - decoded text, and text inside protobuf-framed fields, gets the text check;
  - binary data gets a narrow check on printable runs of 8 or more bytes: an email address with a listed TLD, a dashed SSN, a Luhn-valid card (also with letters glued to it), or a phone number with a cue in the run;
  - CBOR text strings are read by their length prefix, so the header bytes and random neighbours around them no longer hide a value. A key followed directly by its value is checked like a JSON key and value: a phone number under a phone key is a cued phone;
  - a secret after a key word (`key`, `token`, `secret`, `password`, `passphrase`, `credential`, `apikey`), including identifier-style keys such as `api_key` or `clientSecret`, blocks when the value has 16 or more characters. Plural keys and lists under a secret key block like the singular form (`{"api_key": ["..."]}`, a YAML list under `tokens:`);
  - some keys are exempt because they hold ids or counts, not secrets: `pageToken`, `next_page_token`, `cache_key`, `primary_key`, `idempotency_key`, count keys (`max_tokens`, `input_tokens`, `total_tokens`) and data-structure keys (`shard_key`, `hash_key`, `public_key`, `object_key`). `private_key`, `secret_key`, `signing_key`, `encryption_key`, `master_key` and `api_key` still block;
  - a value in a vendor secret format (GitHub, Stripe, AWS, Slack, GitLab and OpenAI tokens, JWTs, PEM private keys, bearer tokens, credentials in URLs) blocks even after an exempt key, so `cache_key: ghp_...` is refused;
  - qualified phone keys (`phone_ext`, `mobile_num`, `callbackNumber`) count as phone cues;
  - a value longer than `max_opaque_bytes` is refused unscanned (see Added), and the scan of large values is close to linear: a test holds a 4 times larger value under 8 times the CPU time;
  - when a finding's offsets cannot be mapped back to the original bytes, the request is blocked (fail closed).

### Upgrading from 0.2.0

- Some stand-ins differ from 0.2.0. Values already in a vault keep their stand-in, except that vault lookups now fold full-width letters, zero-width characters and Unicode dashes, so a value first stored in such a form can get a new stand-in once. New handles, new non-US addresses and new family-name-first names get the new stand-in shapes. For about one date-shift scope in 370 the shift moved by one day (the fix above).
- If you relied on `X-Outworld-Route` to loosen routing, set `policy.allow_route_header: true`.
- Downgrading a vault is not supported. Version 0.2.0 can still open a vault written by this version, but it reads the new format marker and `phone.form` records as ordinary entries, so it treats the stored phone spellings as extra known values.

### Known gaps

The full list, by area, is in the README under [Known gaps](README.md#known-gaps). The most important:

- Names in non-Latin scripts are not detected without an NER sidecar.
- Numbers sent as JSON numbers in the request, including inside tool call arguments, are not inspected (JSON text inside a decoded opaque value is read as text).
- In binary opaque values, phone numbers with no cue word next to them are not checked.
- The OpenAI Responses API (`/v1/responses`) is not supported.
- Month and year only (`March 2024`), bare years, weekdays and relative dates are not shifted.

## [0.2.0] - 2026-11-22

### Added

- Native Anthropic Messages endpoint (`/v1/messages`, streaming, tool use, `count_tokens`), so Claude Code and other Anthropic clients can point at Outworld.
- Built-in name detector on embedded public-domain name tables, with no model: full names, lone first names, particles, surname-first forms, initials, lowercase names, labels, kinship words, chat speakers, profile slugs and names inside `first.last@` addresses.
- Dates in six more languages, compact, airline and spoken forms. National and spoken phone numbers, labelled IDs and secrets, bare hex keys, non-US street addresses, wider honorific and company-suffix lists.
- OpenAI Privacy Filter NER sidecar. The GLiNER sidecar gains chunking of long texts.
- Integration guides for Claude Code, LiteLLM and Open WebUI.
- Evaluation against the Anthropic API, a per-config matrix, and two held-out corpora written without access to the detector code.

### Changed

- Two-pass masking: every text in a request is detected before any is masked, so a name recognised late is also masked earlier.
- A transcript memo keeps already-sent text byte-identical across turns.
- Detectors and patterns run concurrently on large texts.

### Fixed

- The leak check no longer blocks on its own output next to an initial or name particle.

## [0.1.0] - 2026-11-09

Initial public release.

- OpenAI-compatible privacy gateway (`/v1/chat/completions`, `/v1/completions`) with routing per request: `masked`, `local`, `passthrough` or `block`.
- Pattern detection of emails, phones, addresses, IDs, cards, keys, one-time codes, magic links and dates, plus a dictionary of your own people and an optional GLiNER sidecar.
- Realistic, deterministic stand-ins kept in an encrypted vault (AES-256-GCM), date shifting, and rehydration of answers including streams.
- Leak check on every outbound payload.
- `outworld` CLI (`serve`, `mask`, `unmask`, `keygen`, `health`) and an evaluation harness.
